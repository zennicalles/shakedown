# Real-model results: Claude Haiku 5.5, 2026-11-05

**Method.** Each framework's real agent loop and recovery path (examples/*/real-model.test.ts) on `claude-haiku-5-5` through the Anthropic API. Same task everywhere: *"Ticket T-1: refund £50 of charge ch_1 and email ada@example.com"*, with tools `lookup_charge` (read), `refund` and `send_email` (writes) against Shakedown's stateful fakes. Each scenario runs a baseline plus 9 faults. Naive-tool scenarios were run **4 times**; fixed-tool scenarios (ledger + logical key sent downstream) **once**.

**Reading the cells.**
- **duplicate**: something happened twice (refund over £50 or 2 refunds, or more than 1 email). A safety bug.
- **incomplete**: the job stopped short (refund missing, or no email). A completion bug, not a duplicate.
- **hollow**: a pass where the resumed or redelivered job made no write calls. It found the work done or refused to run, so the pass says nothing about idempotency.

**Known caveats.**
- Run 1 of the AI SDK naive scenario used a resume path that replayed a finished conversation verbatim. The API rejected it, so that redelivery "pass" is hollow for a different reason. Fixed before runs 2-4 (`resumeMessages()`).
- One model (Haiku 5.5) only. Versions: ai 7.0.162, @openai/agents 0.21.0 (via @openai/agents-extensions aisdk + @ai-sdk/anthropic), @langchain/langgraph 1.7.0 / langchain 1.6.1, @mastra/core 1.82.0, @modelcontextprotocol/sdk 1.32.2.
- **job-redelivery rows are not meaningful here.** They were measured before two resume-path fixes: the AI SDK replaying a finished conversation, and the OpenAI Agents approval worker giving up on the SDK's "start a new run" error. Under the current core, those cases report as UNTESTED instead of passing. Don't quote them.
- Raw data: haiku-5-5-2026-11-05.json.

**Same-framework experiment (the OpenAI Agents default error text).** `examples/openai-agents/error-text-experiment.test.ts`: naive tools, `timeout-after-commit on refund`, 6 runs each. The model and tools are the same; only the tool error text differs.

| Error text the model sees | Refund issued twice | Looked up the charge before retrying |
|---|---|---|
| SDK default: "An error occurred while running the tool. Please try again." | 6/6 | 0/6 |
| Custom errorFunction passing the real error: "TimeoutError: Request to refund timed out ..." | 0/6 | 6/6 |

With the default text, every run went `lookup_charge -> refund (timeout) -> refund -> send_email`. With the real error, every run went `lookup_charge -> refund (timeout) -> lookup_charge -> send_email`.

**Reproduce.** From the repo root, after `pnpm install` there and `pnpm install --ignore-workspace` in each `examples/<fw>`:

```sh
export ANTHROPIC_API_KEY=...
export SHAKEDOWN_MODEL=claude-haiku-5-5            # ai-sdk
export SHAKEDOWN_ANTHROPIC_MODEL=claude-haiku-5-5  # openai-agents
export ANTHROPIC_MODEL=claude-haiku-5-5            # langgraph, mcp
# mastra needs the provider prefix: SHAKEDOWN_MODEL=anthropic/claude-haiku-5-5
for fw in ai-sdk openai-agents langgraph mastra mcp; do
  npx vitest run --maxWorkers=1 --silent=false examples/$fw/real-model.test.ts > real-$fw.log
done
# repeat the naive scenarios: add  -t naive  and run 3 more times
node scripts/summarize-reports.mjs real-*.log
```
